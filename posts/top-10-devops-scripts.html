Why Scripts Matter in DevOps

As DevOps engineers, we deal with repetitive tasks every single day — checking server health, analyzing logs, cleaning up unused resources, monitoring certificates, and more. Writing small, reusable scripts for these tasks doesn't just save time — it eliminates human error and creates a consistent, auditable workflow.

Here are 10 scripts I use almost daily. Each one is designed to be practical, portable, and easy to extend. Drop them into your ~/bin directory, make them executable, and you'll wonder how you ever lived without them.

1. Server Health Check

This script gives you a quick snapshot of a server's vital signs — CPU, memory, disk, and uptime — in a single command. Perfect for morning checks or quick triage during incidents.

#!/bin/bash
# server-health.sh — Quick server health overview

echo "=============================="
echo "  SERVER HEALTH CHECK"
echo "  Host: $(hostname)"
echo "  Date: $(date '+%Y-%m-%d %H:%M:%S')"
echo "=============================="

# Uptime
echo -e "\n--- Uptime ---"
uptime

# CPU Load
echo -e "\n--- CPU Load (1/5/15 min) ---"
LOAD=$(cat /proc/loadavg | awk '{print $1, $2, $3}')
CORES=$(nproc)
echo "Load: $LOAD | Cores: $CORES"

# Memory Usage
echo -e "\n--- Memory Usage ---"
free -h | awk 'NR==2{printf "Used: %s / %s (%.1f%%)\n", $3, $2, $3/$2*100}'

# Disk Usage
echo -e "\n--- Disk Usage ---"
df -h | awk '$5+0 > 0 {printf "%-20s %s used of %s (%s)\n", $6, $3, $2, $5}'

# Top 5 processes by CPU
echo -e "\n--- Top 5 Processes (CPU) ---"
ps aux --sort=-%cpu | head -6

echo -e "\n=============================="Bash
Pro Tip

Add this to a cron job that runs every hour and pipes output to a log file. You'll have a lightweight health history without needing a full monitoring stack.

2. Log Analyzer & Error Extractor

Quickly scan through application or system logs and extract errors, warnings, and critical messages with timestamps. Saves you from manually scrolling through thousands of lines.

#!/bin/bash
# log-analyzer.sh — Extract errors and warnings from logs

LOG_FILE="${1:-/var/log/syslog}"
LINES="${2:-50}"

if [[ ! -f "$LOG_FILE" ]]; then
  echo "Error: File '$LOG_FILE' not found"
  exit 1
fi

echo "Analyzing: $LOG_FILE"
echo "-----------------------------------"

# Count by severity
echo "Error count:    $(grep -ci 'error' "$LOG_FILE")"
echo "Warning count:  $(grep -ci 'warn' "$LOG_FILE")"
echo "Critical count: $(grep -ci 'critical\|fatal' "$LOG_FILE")"

echo -e "\n--- Last $LINES Errors ---"
grep -i 'error\|critical\|fatal' "$LOG_FILE" | tail -n "$LINES"

echo -e "\n--- Error Frequency (Top 10 patterns) ---"
grep -i 'error' "$LOG_FILE" | \
  sed 's/[0-9]\{1,\}//g' | \
  sort | uniq -c | sort -rn | head -10Bash

3. Docker Cleanup

Docker accumulates dangling images, stopped containers, and unused volumes fast. This script reclaims disk space safely and shows you exactly what it removed.

#!/bin/bash
# docker-cleanup.sh — Remove unused Docker resources

echo "=== Docker Cleanup ==="
echo "Before cleanup:"
docker system df

echo -e "\n--- Removing stopped containers ---"
docker container prune -f

echo -e "\n--- Removing dangling images ---"
docker image prune -f

echo -e "\n--- Removing unused volumes ---"
docker volume prune -f

echo -e "\n--- Removing unused networks ---"
docker network prune -f

echo -e "\nAfter cleanup:"
docker system df

# Optional: Remove images older than 30 days
# docker image prune -a --filter "until=720h" -f

echo -e "\nCleanup complete!"Bash
Warning

Be careful with docker volume prune on production servers. It will remove all volumes not attached to a running container — including database volumes if the container is stopped.

4. Kubernetes Pod Restart Monitor

Pods that keep restarting often indicate OOMKills, crashloops, or failed health checks. This script lists all pods with high restart counts across namespaces.

#!/bin/bash
# k8s-restart-monitor.sh — Find pods with high restart counts

THRESHOLD="${1:-5}"

echo "Pods with restart count >= $THRESHOLD"
echo "============================================"
printf "%-40s %-20s %-10s %-10s\n" "POD" "NAMESPACE" "RESTARTS" "STATUS"
echo "--------------------------------------------"

kubectl get pods --all-namespaces -o json | \
  jq -r '.items[] |
    select(.status.containerStatuses != null) |
    .status.containerStatuses[] as $cs |
    select($cs.restartCount >= '$THRESHOLD') |
    [.metadata.name, .metadata.namespace,
     ($cs.restartCount | tostring), .status.phase] |
    @tsv' | \
  sort -t$'\t' -k3 -rn | \
  while IFS=$'\t' read pod ns restarts status; do
    printf "%-40s %-20s %-10s %-10s\n" "$pod" "$ns" "$restarts" "$status"
  done

echo -e "\n--- OOMKilled Pods ---"
kubectl get pods --all-namespaces -o json | \
  jq -r '.items[] |
    select(.status.containerStatuses != null) |
    select(.status.containerStatuses[].lastState.terminated.reason == "OOMKilled") |
    [.metadata.namespace, .metadata.name] | @tsv'Bash

5. AWS Resource Cost Reporter

Get a quick daily cost breakdown from AWS Cost Explorer without logging into the console. Great for keeping an eye on unexpected charges.

#!/bin/bash
# aws-cost-report.sh — Daily AWS cost summary

START_DATE=$(date -d "7 days ago" +%Y-%m-%d)
END_DATE=$(date +%Y-%m-%d)

echo "AWS Cost Report: $START_DATE to $END_DATE"
echo "========================================"

# Total cost for the period
aws ce get-cost-and-usage \
  --time-period Start="$START_DATE",End="$END_DATE" \
  --granularity DAILY \
  --metrics "UnblendedCost" \
  --query 'ResultsByTime[*].[TimePeriod.Start, Total.UnblendedCost.Amount]' \
  --output table

echo -e "\n--- Cost by Service (Top 10) ---"
aws ce get-cost-and-usage \
  --time-period Start="$START_DATE",End="$END_DATE" \
  --granularity MONTHLY \
  --metrics "UnblendedCost" \
  --group-by Type=DIMENSION,Key=SERVICE \
  --query 'ResultsByTime[0].Groups | sort_by(@, &Metrics.UnblendedCost.Amount) | reverse(@) | [:10].[Keys[0], Metrics.UnblendedCost.Amount]' \
  --output table

echo -e "\n--- Month-to-Date Total ---"
MTD_START=$(date +%Y-%m-01)
aws ce get-cost-and-usage \
  --time-period Start="$MTD_START",End="$END_DATE" \
  --granularity MONTHLY \
  --metrics "UnblendedCost" \
  --query 'ResultsByTime[0].Total.UnblendedCost.Amount' \
  --output textBash

6. SSL Certificate Expiry Checker

Expired SSL certificates cause outages that are embarrassing and preventable. This script checks multiple domains and warns you before certificates expire.

#!/bin/bash
# ssl-check.sh — Check SSL certificate expiry for multiple domains

DOMAINS=("example.com" "api.example.com" "app.example.com")
WARN_DAYS=30

printf "%-30s %-15s %-12s %s\n" "DOMAIN" "EXPIRES" "DAYS LEFT" "STATUS"
echo "-----------------------------------------------------------------------"

for domain in "${DOMAINS[@]}"; do
  EXPIRY=$(echo | openssl s_client -servername "$domain" \
    -connect "$domain:443" 2>/dev/null | \
    openssl x509 -noout -enddate 2>/dev/null | \
    cut -d= -f2)

  if [[ -z "$EXPIRY" ]]; then
    printf "%-30s %-15s %-12s %s\n" "$domain" "N/A" "N/A" "UNREACHABLE"
    continue
  fi

  EXPIRY_EPOCH=$(date -d "$EXPIRY" +%s)
  NOW_EPOCH=$(date +%s)
  DAYS_LEFT=$(( (EXPIRY_EPOCH - NOW_EPOCH) / 86400 ))
  EXPIRY_SHORT=$(date -d "$EXPIRY" +%Y-%m-%d)

  if [[ $DAYS_LEFT -lt 0 ]]; then
    STATUS="EXPIRED"
  elif [[ $DAYS_LEFT -lt $WARN_DAYS ]]; then
    STATUS="WARNING"
  else
    STATUS="OK"
  fi

  printf "%-30s %-15s %-12s %s\n" "$domain" "$EXPIRY_SHORT" "$DAYS_LEFT" "$STATUS"
doneBash
Pro Tip

Pipe the output to a Slack webhook for daily automated certificate reports. Add the domains to a config file instead of hardcoding them for easier maintenance.

7. Automated Database Backup

A simple but reliable script to back up PostgreSQL or MySQL databases, compress them, and clean up old backups. Schedule it with cron for hands-free protection.

#!/bin/bash
# db-backup.sh — Automated database backup with rotation

DB_HOST="localhost"
DB_USER="backup_user"
DB_NAME="myapp_production"
BACKUP_DIR="/backups/database"
RETENTION_DAYS=7
TIMESTAMP=$(date +%Y%m%d_%H%M%S)
BACKUP_FILE="${BACKUP_DIR}/${DB_NAME}_${TIMESTAMP}.sql.gz"

# Create backup directory
mkdir -p "$BACKUP_DIR"

echo "Starting backup: $DB_NAME"

# PostgreSQL backup (switch to mysqldump for MySQL)
pg_dump -h "$DB_HOST" -U "$DB_USER" "$DB_NAME" | \
  gzip > "$BACKUP_FILE"

if [[ $? -eq 0 ]]; then
  SIZE=$(du -sh "$BACKUP_FILE" | awk '{print $1}')
  echo "Backup successful: $BACKUP_FILE ($SIZE)"
else
  echo "ERROR: Backup failed!"
  exit 1
fi

# Cleanup old backups
echo "Removing backups older than $RETENTION_DAYS days..."
find "$BACKUP_DIR" -name "*.sql.gz" -mtime +$RETENTION_DAYS -delete

# List remaining backups
echo -e "\nCurrent backups:"
ls -lh "$BACKUP_DIR"/*.sql.gz 2>/dev/nullBash

8. Git Repository Stats

Get an instant overview of your repo — recent commits, contributors, branch status, and uncommitted changes. Useful during standups or when onboarding to a new project.

#!/bin/bash
# git-stats.sh — Quick repo overview

echo "=== Git Repository Stats ==="
echo "Repo: $(basename $(git rev-parse --show-toplevel))"
echo "Branch: $(git branch --show-current)"

echo -e "\n--- Last 5 Commits ---"
git log --oneline -5 --decorate

echo -e "\n--- Uncommitted Changes ---"
CHANGES=$(git status --porcelain | wc -l)
echo "Modified/Untracked files: $CHANGES"

echo -e "\n--- Branch Summary ---"
echo "Local branches:  $(git branch | wc -l)"
echo "Remote branches: $(git branch -r | wc -l)"

echo -e "\n--- Top 5 Contributors (All Time) ---"
git shortlog -sn --all | head -5

echo -e "\n--- Lines of Code ---"
git ls-files | xargs wc -l 2>/dev/null | tail -1

echo -e "\n--- Ahead/Behind Remote ---"
git rev-list --left-right --count HEAD...@{upstream} 2>/dev/null | \
  awk '{print "Ahead: "$1" | Behind: "$2}' || \
  echo "No upstream branch set"Bash

9. Service Port Checker

Quickly verify that all your critical services are listening on the expected ports. Essential after deployments or when debugging connectivity issues.

#!/bin/bash
# port-check.sh — Verify services are listening on expected ports

declare -A SERVICES=(
  ["nginx"]="80"
  ["nginx-ssl"]="443"
  ["ssh"]="22"
  ["postgresql"]="5432"
  ["redis"]="6379"
  ["app-server"]="8080"
  ["prometheus"]="9090"
  ["grafana"]="3000"
)

HOST="${1:-localhost}"

printf "%-20s %-10s %s\n" "SERVICE" "PORT" "STATUS"
echo "------------------------------------------"

for service in "${!SERVICES[@]}"; do
  port="${SERVICES[$service]}"

  if timeout 2 bash -c "echo >/dev/tcp/$HOST/$port" 2>/dev/null; then
    STATUS="OPEN"
  else
    STATUS="CLOSED"
  fi

  printf "%-20s %-10s %s\n" "$service" "$port" "$STATUS"
doneBash

10. Disk Usage Alert

Monitor disk usage and send alerts when partitions cross a threshold. This is your last line of defense before a disk-full outage takes down your services.

#!/bin/bash
# disk-alert.sh — Alert when disk usage exceeds threshold

THRESHOLD="${1:-80}"
ALERT_FOUND=0

echo "Checking disk usage (threshold: ${THRESHOLD}%)"
echo "============================================"

while IFS= read -r line; do
  USAGE=$(echo "$line" | awk '{print $5}' | tr -d '%')
  MOUNT=$(echo "$line" | awk '{print $6}')
  SIZE=$(echo "$line" | awk '{print $2}')
  AVAIL=$(echo "$line" | awk '{print $4}')

  if [[ $USAGE -ge $THRESHOLD ]]; then
    echo "ALERT: $MOUNT is at ${USAGE}% (${AVAIL} free of ${SIZE})"
    ALERT_FOUND=1

    # Find largest files on this mount
    echo "  Top 5 largest files:"
    find "$MOUNT" -xdev -type f -exec du -sh {} + 2>/dev/null | \
      sort -rh | head -5 | sed 's/^/    /'
    echo
  fi
done < <(df -h | tail -n +2)

if [[ $ALERT_FOUND -eq 0 ]]; then
  echo "All partitions are below ${THRESHOLD}% usage."
fi

Conclusion

These 10 scripts cover the most common tasks a DevOps engineer faces daily. The key principles behind all of them are the same:

  • Automate the repetitive. If you do it more than twice, script it.
  • Make output readable. Formatted tables and color-coded statuses make scripts usable by the entire team.
  • Add safety checks. Always validate inputs, check if files exist, and handle errors gracefully.
  • Keep them simple. A 50-line script that works is better than a 500-line framework nobody maintains.
  • Version control everything. Put your scripts in a Git repo — they're infrastructure too.

The best DevOps engineers aren't the ones who work the hardest — they're the ones who automate themselves out of repetitive work so they can focus on what actually matters.

Start with the scripts that match your daily pain points, customize them for your environment, and build up a personal toolkit that makes you more effective every day.
